## 流程协议

| 接口                                                          | 行为                                                                         |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `validateProgram(program, host)`                              | 预检所有分支的操作和查询是否受支持，限制格式及结构规模；不是牌效正确性的证明 |
| `startFlow(program, context, host)`                           | 运行至玩家选择、领域操作或流程结束                                           |
| `chooseFlow(state, actor, requestId, ids, host)`              | 校验决定者、请求ID、数量、唯一性及候选项后继续                               |
| `completeOperation(state, requestId, receipt, consequences?)` | 由权威引擎提交实际结果，可插入子流程；客户端不能直接确认操作                 |

节点包含`sequence`、`let`、`if`、`repeat`、`for-each`、`choose`、`operation`。表达式仅支持约定的JSON查询、算术、比较和集合处理，不接受任意JavaScript。

循环次数和遍历集合在进入时取快照，循环内部查询读取每次恢复后的局面。负数和非整数重复次数拒绝执行；#68按当前规则解释显式写`max(0, 4-progress)`，不是框架默认归零。每个嵌套块有自己的绑定作用域。#84／85复用军力占据查询并在开始时固定地区集合；#95／99在卡模板显式计算绝对差。

`FlowContext`分别存出发阵营、原回合方、受益方和归还决策方，每个玩家选择另有明确actor。#30使用经济的实际位移回执，让RC和NSDAP逐格交替选择；不能把请求移动量当实际结果，也不能把受益方临时改成回合方。#98将两段实际移除回执相加后再授予非城市放置，#105按年度顺序逐方选择归还。

操作回执记录`actual`、`spaces`、`pieceIds`、`rolls`等实际结果。#7只揭示刚部署的军团，不会误选既有地图军团。无合法目标时按事件6.1跳过无法执行的指令；“可”与“至多”允许选择零。

## 单一队列与命令事务

`dispatch`克隆输入，再校验命令、执行效果、检查不变量。失败返回原状态，不保留部分影响力、手牌、随机数或日志变更。浏览器只提交Command，不提交可信状态快照。

`flow-start`建立流程；选择变成普通`pending`；领域操作生成`domain-job`，玩家选项只携带JSON数据。执行赠送行动时先隔离父队列，依次完成行动、借兵、战斗、归还等子效果，清除授权上下文，再处理下一次赠送行动，最后确认父操作回执。赠送行动不扣正常回合预算，但沿用普通行动的经济、势力范围、人口、库存与行动历史限制。

事件直接放置和赠送“放置影响力行动”明确分开，遵循2026-10-16官方勘误。原子替换仅为自身移除和放置绕过同一步冲突，不绕过先前行动的历史或暗杀标记。

`legalActions`复用规则校验，事件候选也用`applyAction`在副本上预检。候选生成不得消耗真实随机数、泄露未揭示身份或修改真实棋盘。

## 持续规则与领域后续效果

`policies.ts`集中本批加值、设值、下限及条件，例如#55强度、#56影响力数量、#58／#62部署权限、#19／#59立场步数。原有#1领导变化、第48条、死敌和总罢工仍在各自领域入口触发；并未假装实现适用于所有后续卡的通用触发器排序器。

#5锁定柏林控制至下一次完整选举；#117提前选举会解除锁定，#82公投不解除锁定，也不更新议会、席位、第48条或清场。时代期限记录于卡定义，历史剧本在切换时代时统一处理到期；实验局仍不能作为跨时代正式剧本。

#119使用独立的`article48Removed`保留永久移除状态，不由119是否仍持续生效推导。#124通过`seats.uses`和`seatsUsesRemaining`统一计算余量；刷新议席时清零。#117调用完整选举结算的提前选举分支，清场插到事件续点之前，不排入`finish-round`，也不重置预约的普通选举。#118调用立即胜利操作。#122／132／146的PV读取复用`previewElection`，没有选举副作用。

#125的杠杆替换沿用可用棋子、归还选择和黑杠杆清理规则；#133允许从地图调动国防军；#137读取归还操作去重后的`spaces`回执逐地补偿；#141只在同一次替换操作内允许连续处理同地影响力，不放宽先前独立行动的冲突限制。

部队移动完成后处理死敌；事件直接部署也追加死敌检查。突击流程为声明目标、两侧借兵及许可、忠诚、中产支持、双方掷骰、分配命中、战后momentum和影响力代价。双方命中在损失前锁定。自由军团身份开局由独立种子流固定；翻面、移出或再次部署不重抽。

## 增加牌或行动

先核对牌面、规则与勘误，明确前置、决定者、是否可选、实际次数、选择范围和持续期限。模板仅组合已注册操作；新增机制先补领域处理器，再通过语义测试和命令重放，最后登记可执行并更新覆盖文档。

新增普通行动扩展Action联合类型、`applyAction`和候选枚举。多步过程使用效果队列，不把中间状态放在DOM中。需要限定地域时，后续移动、忠诚检定、附加暗杀也必须继承范围。

## 保存与验证

当前格式为`weimar-0.7.0`，保存开局参数（剧本、种子、测试牌与是否预置前置）及成功命令。导入、撤销、重做均从开局重放，随机数来自状态中的固定种子。暂停中的事件选择也能恢复。

0.1–0.6文件可尝试按新规则重放；0.6的开局和完整Fate战役已有新旧源码对照验证。更早版本的规则与选择ID变更可能拒绝旧记录或改变结果，不承诺任意旧版本逐位一致。新版浏览器使用独立保存键，保留原自动存档。

目前为共享本机热座工具，尚无登录身份映射或隐藏信息隔离。规则和完整状态对本机调试工具可见，不能作为联机防作弊边界。

验证结果与浏览器路径见[规则覆盖](rules-coverage.md)，本批解释和边界见[衰落时代说明](batch-113-151.md)。`reference/drafts/card-batch/`是早期未验草稿，不参与构建。

## 0.6 战役生命周期

`decks.ts`以牌面定义生成实体卡实例：危机／黄金／衰落包含1／3／4张独立UID的选举牌，按9.1将强制与选举牌混入上层牌堆。教程保留原发牌序列，避免无关重排旧存档。

`lifecycle.ts`复用`Effect`队列和`PendingChoice`，将时间轴清理、年度经济、留牌惩罚和新牌发放拆成可暂停的续接点。归还暗杀全部结束后才执行通胀与推进年份；1930杠杆归还全部结束后才允许设置年度顺序。`eraChange`记录待切换时代，在`set-order`后按新顺序扣留牌；惩罚数预先快照，移除多少影响力不改变发牌扣减。最后统一到期持续牌、将旧牌移至`removedCards`、依次整批发牌，再进入行动阶段。

终局复用留牌队列，1933所有阵营完成惩罚后，根据联盟是否留牌决定进入完整最终选举或联盟直接胜利。对局提前获胜不会继续结算年末。新状态由开局参数和命令历史重建；存档0.6新增`scenario: fate`，保留旧版导入入口。

## 0.7 历史剧本

`scenarios.ts`存四个历史剧本的数据配置，`setup.ts`按配置复制轨道、立场、实体棋子及地图数据。提取Fate配置时保留原棋子生成顺序、洗牌序列和日志，避免旧命令中的棋子ID失效。`fixedStances`与`reactionLimited`分别复用于行动验证、可用棋子、卡牌立场变化和轨道约束；事件前置仍由`ruleset`控制，黑日保留标准前置检查。

`prepareBlackSun`只预置持续区和移除区，不调用事件队列。1930由既有`era-deal`到期这些牌并发衰落牌。`lifecycle.ts`从配置读取终年，革命时代于1923进入最终选举，其余历史剧本复用1933留牌路径。

`call-extra-election`是独立命令，记录已使用机会及待结算状态，消耗所选议会牌或议席，不借用普通议会效果。选举阶段以普通或额外任一预约进入同一个完整周期，结算后清待办、保留已用次数。革命终局PV修正在`previewElection`统一计算，仅全国PV变化；最终计票与界面预览共用这一路径。详见[剧本说明](scenarios-0.7.md)。
