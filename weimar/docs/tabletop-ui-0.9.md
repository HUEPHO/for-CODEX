# 棋盘UI · 0.9.1

按用户要求，以规则书第48页的“共和国的命运”摆局图为布局参考：原版印刷图保持固定，活动棋子作为独立图层放在上层。实际底图直接使用已有的中文`public/assets/board.webp`，未裁改、重画或烘焙进开局棋子。

## 当前行为

- 默认打开棋盘。26个地区根据实时局面显示每个影响力方块、部队及功能标记；同种、同阵营、同正反面的棋子叠放并标数量。
- 0.9.1使用TTS中的34张原版贴图，覆盖干部、杠杆、改革、罢工／起义、暗杀、部队、轨道和议会控制；中产支持为白色棋子，集团为黑色方块，影响力沿用四色方块。未揭示自由军团使用相同正面，揭示后显示原版带F的忠诚面。地图、地区详情和玩家库存均不读取秘密忠诚值。
- 经济、进步、反动、美苏协定、年份／半年、阶段、momentum、年度顺序、美元依赖，以及轨道待解锁棋子均放在底图对应位置。
- 议会控制位置显示当前持有人，用淡色表示已使用；持续事件的实际牌面放入左下印刷区域，点击可以放大。
- 点击地区更新右侧详情。在有地区目标的行动中，当前合法地区显示金色虚线；点地区会同步选择合法目标，仍需点击“执行行动”提交规则命令。
- 有多个合法数量／单位选项时可继续使用目标下拉框。事件的多步选择保留原决定者和选择入口，不猜测选项文字或任意拖动棋子。
- 适应窗口显示整张棋盘；100%–250%相对于适应大小缩放，放大后用滚动条查看。“专注棋盘”收起顶部概要，“返回全桌”恢复。下方手牌仍为原有合法可见手牌。
- 对局、实验、撤销和存档收进“对局与存档”；玩家区区分可用与待解锁棋子。浏览器热座和Steam投影共用显示模块，命令仍走各自原有提交入口。

## 代码与坐标

`src/ui/board-layout.ts`集中存储印刷区域和轨道坐标。底图4096×2656，叠层使用1800×1167.1875坐标，保持同一比例；缩放整个底图和叠层，避免两者漂移。

`pieces.ts`在SVG中渲染原版贴图、实物形状及公开标签，按公开属性合并棋子；`tabletop.ts`只消费状态，生成地图、地区详情和玩家库存。显示过程中不变更游戏状态、不执行规则、不把渲染结果当成命令。

`src/main.ts`在地图选择后查找引擎／房主给出的合法行动。只更新选择，提交仍由用户确认；实际数量由引擎决定。UI变化不改变本地`weimar-0.7.0`存档格式或联机`weimar-steam-1`协议。

原版图片位于`public/assets/tokens/`，直接复制TTS源文件字节，未重新设计图案；SVG仅按实物圆形／圆角轮廓裁切。`provenance.json`记录源GUID、正反面、URL和SHA-256。通过`python scripts/import-tokens.py --tts PATH/TS_Save_13.json`可重新导入；日常运行使用随Git和安装包提供的本地素材，无需连接Steam图片服务器。玩家垫板仍使用简化库存区。

## 联机参考

已阅读用户给出的[五子棋联网测试](https://chatgpt.com/share/6ad737eb-e48c-83e8-9a1c-327586712fea)，并检查本机`Steam-Gomoku-Codex-Handoff.zip`中的`main.cjs`。初始化为`init(480)`，建房为`createLobby(2, 2)`，传输为`sendP2PPacket(..., 2, ...)`及`readP2PPacket`，使用同房间成员校验和`acceptP2PSession`。

用户于2026-10-20反馈该方案已实测成功；这是交接包原先“尚未收到结果”之后的新信息。WEIMAR沿用同一绑定与传输接口。差别是五子棋为公开双人房间、Node＋本机浏览器，WEIMAR为好友四人房间、Electron与分玩家可见状态。本轮没有据此替换Steam路线，也没有把五子棋的完整棋局广播套用到隐藏手牌游戏。
