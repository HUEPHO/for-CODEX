# 交互权限与持续收益架构重构 · 2026-09-17

本批按开发复盘调整现有架构，让新增事件或回应复用同一套责任人、待办权限和收益选项。继续使用原生模块、原游戏状态和房间服务，不迁移前端框架，不改变已确认规则。

本批没有新增牌面：仍为26张非转折点事件自动结算、2张转折点即时处理、5张持续效果；剩余32张事件、9张持续效果、3张替换国家。当前模块导航见[ARCHITECTURE.md](ARCHITECTURE.md)。

## 复盘发现与已实现调整

先前新增一个回应流程，需要分别修改引擎守卫、阶段责任人、房间权限、等待面板和页面按钮。持续收益曾出现“按钮可点、提交后服务端拒绝”的差异；按卡牌继续追加分支容易遗漏其中一层。

此次还复现了人工事件权限差异：轮到美国确认、中国尚未确认时，中国可合法补记资源，但地图军队和介入按钮也显示可用，提交后却被房间层拒绝。本批保持原服务端范围，以同一策略禁用这些按钮，没有扩大非责任席位的地图权限。

| 已完成调整 | 实际边界 |
| --- | --- |
| 提取 `game-constants.js` | 读取势力／地区／资源名称不再要求导入引擎 |
| 新增 `interaction-state.js` | 集中读取事件、收益、发展、结盟、卡序的交互、责任人和动作限制 |
| 共用 `action-policy.js` | 引擎、房间、界面共用动作类型／待办准入及拒绝原因，保留手动例外与席位限制 |
| 新增 `control-command.js` | 控件映射为动作类型，界面应用共享策略并保留领域条件的禁用结果 |
| 调整流程面板分发 | 使用交互种类选面板，使用责任人／所属人及公开展示标记处理等待 |
| 拆分收益规则与执行 | 中东欧／中伊的责任人、选项、可用原因和计划统一定义；执行器应用计划、处理资源上限并存账目 |
| 拆分战役优势预检 | 状态模块检查资产归属／未用，独立完整预检供界面与序列启动共用 |
| 增加结构与行为检查 | 检查只读依赖、根模块导入图、脱敏一致、嵌套恢复和收益选项契约 |

共享策略不替代领域校验。允许 `resolveSequenceStep` 不代表任意目标、费用或参数都有效；服务端仍在完整状态上执行原卡牌／投资／贸易等校验。客户端也不能自行提交收益操作计划让服务端照单执行。

## 保留的嵌套流程

交互显示和责任人优先级为：事件分发／结算、持续收益、发展选择、追加结盟、卡牌序列。没有待办时，使用普通阶段或逐方结算责任人。

准入须同时满足尚未完成的待办限制。例如“外交出访 → 开放外交 → 缩减官僚”保留原卡、追加结盟与发展选择。选牌期间不能提前结盟或继续原卡；选牌后恢复结盟，再恢复原卡。事件命令维持原优先处理边界。

战役优势仍在购入时立即抽选资产，可以不盖手牌使用一张合法资产。`finishBattlefield` 返回选择后，同一次 `applyAction` 内的 `startBattlefieldAsset` 先完成完整预检，再暂停原卡并翻面资产。资产及其追加出牌、他方回应完成后才恢复 `battlefieldReturn`，不会多消耗普通行动。

持续收益保留中国 → 欧盟 → 中国的责任切换，即使欧盟已领过本轮自己的投资收益也能回应。基础收益只先发一次，全部持续效果结束后才完成中国的投资回报；中国排最后时同样先结完再进入繁荣。

## 新增交互的接入步骤

1. **确定存档和恢复位置。** 明确owner、当前responder、轮次／步骤、已完成内容，以及父流程暂停和恢复方式。已有交互能够表达时复用原待办。
2. **注册只读交互。** 在 `interaction-state.js` 定义存在条件、责任人、所属人、提示及动作集合。明确嵌套优先级与并存限制；读取不能依赖执行器或私密字段。
3. **接入执行入口。** 由 `engine`／`flow` 或现有领域模块分发动作。领域模块继续负责参数、费用、目标、阶段和次数校验，失败保持原状态；类型准入不会自动创建处理器。
4. **接入面板与控件。** 在 `flow-ui` 交互渲染表加入面板；公开回应可用 `shared` 标记。新提交控件声明 `data-command` 或加入 `control-command` 映射，并接入真实事件处理函数。输入控件及未映射控件仍有页面上下文回退，不能把“已渲染”当成权限接入完成。
5. **核对脱敏和恢复。** 新增秘密内容时更新 `playerView`。覆盖四方责任人／权限一致、他方回应、父流程恢复、刷新、失败不变及重试去重。

## 新增投资回报持续效果的接入步骤

1. 在 `INCOME_RULES` 定义效果名称、所属玩家、初始选择及回应状态。回应状态字符串必须唯一，并视为需要兼容的存档标识。
2. 为选项提供公开标签、不可用原因和纯计划函数。计划返回下一回应状态、是否完成、操作列表及收据片段，不直接修改状态；界面可用性与服务端拒绝来自同一规则。
3. 复用现有 `money`、`resource`、`useCommerce` 操作。确需新增操作时，在执行器明确实现，并补前置校验、资源上限和失败不变检查，不能只添加UI选项。
4. 事件通过 `grantEventEffect` 取得效果。收益元数据进入 `EVENT_EFFECTS`，投资回报通过 `incomeEffects` 识别本方实际取得且已支持的规则；不能从目录自动授予。
5. 验证所有回应分支、费用不足、错误席位、未知状态、溢出和每轮一次；从取得效果的事件连续走到后续投资回报，确认实际触发及阶段推进。

目前规划／执行分离仅覆盖中东欧和中伊两项收益。其他牌面继续使用原领域代码，不能据此认为所有事件已声明化，或任意新牌只填数据即可完成。

## 存档与权限兼容

- 不改游戏／房间版本、数据库结构、本地存档键或已有状态字段。没有持续效果的旧局沿用原投资回报，不补发历史收入。
- 保留 `pendingIncome` 的 `round`、`owner`、`base`、`remaining`、`active`、`receipts` 及 `ceeOffer`、`ceeFallback` 的含义；旧待办没有 `active` 时按初始选择读取。
- 未知收益、未知回应、空待办和轮次不匹配会显示并拒绝，不默认解释成中东欧选择；本批不自动修复无法解释的存档。
- 保留发展／结盟／卡序并存、战役优势父流程和旧卡序贸易初始化入口；只读层不重新生成已结算步骤。
- 隐藏开局选牌时仍保留 `setupPending`，四席继续用各自 `seatRevision` 并行选牌；不放宽秘密投标、目标或手牌隐私。
- 非责任席位人工窗口仍限原8种 `MANUAL_ACTIONS`，已确认席位关闭窗口；不扩大地图军队、介入和影响力移除权限。
- 房间继续验证身份／席位、版本、重复命令和有限撤销。UI禁用用于说明可操作范围，服务端仍独立校验。

## 依赖边界

原先 `phase-state` 读取责任人却导入事件执行器，令只读层加载大量领域代码；现改为只依赖交互读取。实际循环曾涉及基础行动、国内行动、发展、战役优势、市场动作和序列预检，核心回边为战役优势状态模块导入序列验证器。完整预检移至 `growth-battlefield-availability.js` 后循环消除，没有通过旧模块重导出而重新引入依赖。

`check-architecture.mjs` 限定 `game-constants`、`interaction-state`、`phase-state`、`action-policy`、`event-income-rules` 五个只读模块只能在该层相互依赖，不能导入执行器、UI、I/O或外部包。当前 `dist/` 根目录手写 `.js` 模块的相对静态导入及字面量动态导入图也通过无循环检查。范围不含全项目所有文件，不推断计算得到的任意动态导入目标。

## 浏览器验证

使用独立端口8799和 `.local/architecture-browser` 中的SQLite，普通8787数据库未改动。下列为准备局面的代表机制路径，不是从正式开局连续玩完六轮。

1. **ARC222，人工事件非责任席位。** 中国在等待美国确认时可增加本方资金，100变101；影响力、介入和中国驻军按钮均禁用。界面与原服务端手动权限范围一致。
2. **ARC223，三层嵌套。** 美国“外交出访 → 开放外交 → 缩减官僚”期间资源按钮禁用。选牌移除发展战略后恢复开放外交，刷新仍能继续；跳过追加结盟后返回原牌介入步骤，实际支付4外交，完成行动交中国。
3. **ARC224，收益他方回应。** 中国发起中东欧选择，欧盟在自己的标签页拒绝；中国刷新后支付1消费品获得15资金，再用中伊获得2能源。最终中国115资金，轮到欧盟；非责任席位按钮正确禁用。

上述浏览器路径未见控制台error。程序与浏览器分别验证，不将准备局面操作描述为完整正式对局验收。

## 剩余架构边界

- 事件、卡牌和发展仍有各自执行器。本批集中交互／准入，并迁移两项收益的规划／执行，没有统一所有效果表示。
- `app.js` 仍桥接多种页面事件；新增控件需接入动作映射，没有自动生成全部表单或完整命令schema。
- `flow` 仍使用可并存待办字段和专门的战役优势父流程，未迁移成通用执行栈；新嵌套仍需明确恢复规则。
- 账目用于核对，房间继续快照持久化和有限撤销；未实现完整事件溯源、确定性回放或全部随机过程重演。
- 当前收益规则只读取公开数据。未来含秘密选择的规则须另做脱敏设计，不能直接把完整计划发给所有玩家。
- 牌面未完成项、已有待裁定规则和整体界面升级按原清单推进；本批不部署、不改托管和生产身份方案。
