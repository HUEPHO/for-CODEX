# 四人房间验收记录 · 2026-09-16

按完整功能路径推进，已保存独立检查点；本记录区分浏览器实操与程序验证。

## 本次修改

- 添加 Vite 开发入口，复用原生产房间 API 与独立 SQLite；支持对现有原生 JS 项目进行实际浏览器验收，生产仍使用原 Worker/D1，没有更换游戏框架。
- 浏览器发现本地 HTTP 环境没有 `crypto.randomUUID`，原先导致整张桌面加载失败。改用 `crypto.getRandomValues` 生成 256 位随机标识；保留服务端散列、席位权限和请求去重。
- 房间中未出牌的回合不能直接结束；UI 禁用按钮，服务端也拒绝。可正常选择盖牌放弃行动，空手仍可按原规则放弃并领取奖励。旧手动存档的引擎路径保留。
- 研究购牌显示当前可用研究力，余额不足时禁用购买按钮；服务端费用校验保留。
- 终局房间状态明确显示“对局已结束”，不再误报“开局选牌”。

## 实际浏览器路径

同一浏览器四个独立标签页扮演美/中/欧/俄。基础版新房完成四方起手与资产选择；俄罗斯外交介入验证了不足额禁用及盟国减费后的支付，撤销和刷新恢复同一局面。

中国金砖国家从实际手牌盖牌、支付 30 资金、选择美洲/非洲并逐段放影响力；在两段之间刷新继续。俄罗斯在自己的标签页接受并支付，回到正常轮转，回应没有多消耗一次俄罗斯行动。其余行动使用正常盖牌放弃。

首轮完整走到研究，俄罗斯用 3 研究力取得贸易机会；不足额购买另一张牌未成交。四方依次研究、领取投资回报、选择繁荣与处理威胁，进入第二轮准备。

第二轮国家更新、四方重新选择顺位、统一初级生产、俄罗斯实际生产 1 消费品并支付所需资源、四方确认焦点，均已通过浏览器完成，回到第二轮行动。

第三/第六轮计分用完整房间模拟生成的独立本地局面复核；第三轮局面已能加入大厅，但浏览器在席位恢复确认窗口发生连接超时，确认接口与按键恢复均未成功。因此这两个计分局面的浏览器操作和终局状态文案未完成实操验收。相应房间流程、计分与终局视图渲染在程序检查中通过。没有将测试局面写入生产数据库，也没有将本次称作“六轮浏览器真人整局通过”。

## 完整六轮程序验证

`npm run test:room-game` 通过：基础版 304 条房间命令，启用两个扩展及行政命令 323 条房间命令。经真实房间命令处理器完成入座、个人开局选择、合法放弃行动、研究购牌、各阶段责任玩家、准备/选位/生产/焦点、第三与第六轮计分、终局阻止继续前进，以及四方脱敏视图的流程渲染。

这比纯引擎模拟多覆盖房间权限与四方视图，但不等于所有卡牌组合已做浏览器验收。扩展事件和目标仍使用现有的显式手动确认，不假称扩展效果全部自动完成。

原房间接口/SQLite/四份客户端检查也通过。本次不重复所有逐卡脚本。
