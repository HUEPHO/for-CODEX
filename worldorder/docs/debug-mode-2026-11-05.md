# Debug Mode · 2026-11-05

右上角新增 Debug Mode 按钮。弹窗可选择四个势力，按牌名或势力搜索全部 154 张起始能力、市场能力和战略资产（含基础及扩展，不受本局扩展开关筛选）。能力牌直接加入手牌，保留市场／牌库原牌；资产加入未使用资产区，已使用的同名资产可重新启用，已有可用资产不重复添加。

资金、SP、胜利分、七种资源库存与七项产能支持直接输入或 ± 调整，点击“保存数值”批量保存。库存与产能允许超出通常上限，最低 0；胜利分允许负数。不支付费用、不领取升级奖励、不消耗行动或推进回合。超轨产能带有明确的玩家调试标记，使后续生产能读取；正常对局的产能校验仍沿用原轨道限制。

本机自动保存；多人房间仅当前已入座的房主可调整任何势力。独立 `debug` 命令仍验证身份、版本、重复请求及数据库并发，不通过客户端完整状态回写。其他玩家隐藏手牌仍按原规则脱敏。改动计入日志，并清除调试前的撤回快照。弹窗发现局面已更新会重新读取数值，避免旧表单覆盖新局面。

主要源码：`dist/debug-mode.js`、`dist/debug-mode-ui.js`、`dist/debug-mode.css`；接入 `app.js`、`index.html`、`action-policy.js`、`economy.js` 和 `server/rooms.js`。

验证通过：

- `runtime/node.exe scripts/check-debug-mode.mjs`：跨势力／扩展卡、资产重新启用、超限调试值、普通生产限制、非法输入原子拒绝、房主／席位／版本准入、幂等和手牌隐私。
- `runtime/node.exe scripts/check-architecture.mjs`：依赖无环、共享纯读取权限边界及既有待办准入。
- `.ui-pptx-build/debug-mode-qa.mjs`：1440×900、1200×720 实际浏览器添加卡牌与资产、±／数值保存、刷新恢复、窗口边界；真实 HTTP 房主编辑、他席同步、非房主拒绝、旧表单拒绝和 SQLite 服务重启恢复。浏览器错误为 0，使用独立测试数据库和浏览器存储。

实际截图及结果在 `output/DebugMode截图_2026-11-05/`。若网页服务在本批修改前已启动，关闭原启动终端后重新运行 `Start-Local.bat`，再刷新页面以加载服务端新命令。
