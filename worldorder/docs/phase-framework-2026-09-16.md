# 阶段、扩展结算与终局框架

用户要求先做好大框架。本批在现有原生 ES modules 与房间服务上增加共用流程，不迁移框架、不改生产数据库。

## 可用行为

- 全局进度条展示轮次、阶段、子步骤与当前完成数量。最后一轮不显示研究；未启用 WIT 时不显示事件。
- 本地流程与房间共用同一个操作责任人计算，覆盖研究、准备、余波、卡牌回应、抽弃牌和扩展确认。直接调用流程引擎也验证责任人。
- 事件处理完后，四方按顺序核对本方结果。每次确认即保存；刷新续接，四方完成前不能直接进入余波。事件牌的条件、选择和效果仍须手动执行。
- 第3／6轮目标计分按四方顺序推进：选一张尚未使用的目标，人工按牌面计算分数后提交。支持“现在加分”和“已在面板加分，仅登记”，避免补记时重复发奖。已用目标不能在第6轮再用。
- 已确认的玩家不能在同一扩展结算步骤继续补记。按既有规则可撤销自己最后一步；其他玩家接续后不能跨步撤销。
- 研究、准备、余波及扩展确认保存公共数值账目，区分自动结算与手动记录。账目仅含公开数字，不保存目标卡ID、抽到的牌或手牌快照。
- 终局单独保存未用资产／行政命令奖励明细，并标明已包含在总分中。终局刷新不重复发奖。

## 模块与接入方式

| 模块 | 职责 |
| --- | --- |
| `phase-state.js` | 阶段定义、余波步骤、当前责任人、结算任务标识和只读进度；不依赖 DOM 或房间封装 |
| `phase-settlement.js` | 扩展步骤的共同提交校验、四方完成记录；目前接入事件核对和目标登记 |
| `settlement-journal.js` | 在引擎成功完成一次动作后记账；失败动作不产生记录，房间重试沿用原有去重 |
| `phase-ui.js` | 全局进度、结算表单、公共账目；同时供本地与房间显示 |
| `sequence-progress.js` | 复用公共数值变化计算，已有卡牌多段账目继续使用 |

后续新增结算步骤先在 `phase-state.js` 定义时机和责任人，再在 `phase-settlement.js` 接入处理器。自动目标判断可替换人工分值的计算来源，继续复用选牌、一次性计分、保存、轮转和隐私规则。新卡牌的具体效果仍沿用既有 `card-sequence.js`，不重复建立另一套卡牌引擎。

## 状态与兼容

- `flow.settlement`：当前扩展结算的 key、kind 与 done 列表。key 包含轮次、阶段与余波子步骤，拒绝过期任务。
- `settlementHistory`：已完成扩展步骤的公开确认结果。
- `players.*.scoredObjectives`：已结算目标的轮次、ID、分数及计分方式；给其他席位的视图移除 ID。
- `settlementJournal`：最多保存600条公共账目，界面展示最近12条；不是完整回放系统。
- `finalAwards`：各方终局未用资产／行政命令分数。

上述字段均按需建立，保留原有 `version: 2` 存档。只读预览不写存档，也不补造旧账目。旧存档若已在第6轮、没有目标使用记录，由本人选择此前剩余目标；若已手动加分，使用“仅登记”。已结束的旧局不重算奖励。

## 验证

- `check-phase-framework.mjs`：责任人、四方确认、旧存档只读展示、刷新恢复、撤销、请求重试、错误提交不变更、仅登记不加分、目标重复使用拒绝、目标ID隔离、事件账目、终局一次性奖励。
- `check-flow.mjs` 与 `check-room-game.mjs`：基础版和双扩展完整六轮流程、四方视图及阶段权限通过；最后一次检查的房间命令分别为305和347条（随机市场可能改变购牌命令数）。目标用测试分值0，事件用手动核对，不表示扩展牌面规则已自动化。
- `check-rooms.mjs`：现有身份、并发、SQLite持久化、四客户端同步通过。
- `check-sequence-guards.mjs`、`check-growth-active.mjs`、`check-research.mjs`：相关卡牌回应、最新发展时机裁定、研究和公共账目改动回归通过。
- **浏览器，独立端口8793与测试数据库**：四个标签页完成第3轮地区／多数计分、四方目标、SP计分，进入第4轮准备；第6轮完成同样路径，显示胜者与未用资产4分、行政命令3分，刷新后分数不变；事件逐方确认，中途刷新后保持1/4进度，四方完成后进入余波。

浏览器局面由本地脚本预设到第3／6轮计分前，后续通过真实页面完成。补齐了此前这几个阶段的浏览器验收缺口，未声称从开局到终局连续真人试玩、所有计分组合或事件牌均已验收。
