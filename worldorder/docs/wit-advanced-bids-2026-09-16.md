# WIT 售军、随机竞价与跨席位回应 · 2026-09-16

本批新增7张自动事件，共18张非转折点事件自动结算，另有2张转折点即时处理；40张事件仍人工。复用上一批的混合竞价、军队暂存和影响力规则，没有另建结算流程。未部署，正常本地房间数据保留。

## 新能力

- 出售待命军队也可作为投标：按牌面限定参与者、每人最多2支、每支15资金。揭标才移除军队并发出售收入，无论胜败；这些军队不进入地区，也不付移动费。
- 随机对手出价仅在全部提交后抽取一次，记录在当前事件和公开历史里。刷新、重复请求不能重抽；揭晓之后锁定撤销。对手平局保留事件时，按用户裁定发本人完整投标的SP；牌面写玩家平局获胜时则按胜方计算。
- 事件奖励支持可选付费影响力、可选售军、免费军队移动；可以交由未参与投标的其他玩家选择。军队投到事件牌后，须等这些回应全部完成才进入地区。
- 中俄美洲纽带中可有两个影响力接收者，获胜者最后放置，然后才降低美国永久影响力。待处理顺序及最后一步保存于状态，可跨刷新恢复。
- 按用户本次确认，所有未指定槽位的新增中立影响力都先填空永久槽，满后进入临时队列；原位替换仍留在原槽。
- 已开始的旧人工事件保持人工；旧报价中没有新增售军字段时按0处理，不重算先前已提交的报价。

## 实际验证

- `node scripts/check-event-bids-advanced.mjs`通过：七张牌面的胜／败／平局、出售限制与败方收入、全部随机取值、零出价、加成、多个领奖者顺序、最后降级、SP不足、中立影响力、免费移动来源／总量、费用不足回滚、刷新、命令重试、其他席位权限和揭标撤销保护。
- `check-event-bids.mjs`、`check-events.mjs`通过，保留旧数字报价及既有事件兼容。`check-flow.mjs`／`check-room-game.mjs`通过基础与扩展六轮；人工事件仍以人工确认推进，不能据此宣称全部牌面完成。
- 独立端口8799、独立SQLite房间 `BDA444`，四个实际浏览器席位完成以下连续路径。测试服务固定随机值以验证指定分支；正常服务仍使用正常随机抽取，测试设置未进入产品代码。
  1. 也门：美欧各投1支待命军队，揭标前不发钱／不扣军队，对方看不到投标。揭标后双方各获得15资金、1 SP，军队各减少1；合计2输给对手5，加入抵抗轴心。刷新后对手仍为5，最后揭标不能撤销。
  2. 奥库斯：美国2外交、欧盟0。先在亚太加中立；美国放永久影响力得1分，出售余下1支待命军队得10资金。交由中国席位在资金0时免费移入2支待命军队；结果账目与地图数量相符。
  3. 纳卡：俄罗斯投1支待命军队，付5资金，输给对手4。中亚俄起始影响力原位换中立；军队继续留在事件牌上。刷新后美国自己支付10资金／2外交放永久影响力得1分，俄罗斯不能代操作。完成回应后俄军队才进入中亚。
  4. 俄罗斯核对后进入余波投资回报。此前加入的抵抗轴心在补牌时揭示，加中东中立并替换为下一轮中东冲突；事件区显示18张自动事件与3条已完成事件记录。
- 以上是人工准备局面的代表性浏览器检查，不是从开局连续真人试玩六轮。
